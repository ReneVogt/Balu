# AGENTS.md

## Project Overview

Balu is a from-scratch compiler and language project inspired by terrajobst's Minsk tutorial. The repository is a .NET/Visual Studio solution centered around `src/Balu.sln`.

## Main Projects

- `src/Balu`: Backend compiler library. Contains syntax trees, parser/lexer, binder, symbols, lowering, diagnostics, IL emission, visualization, source text handling, and editor-oriented classification.
- `src/bc`: Command-line compiler frontend. Parses `.b` source files, creates a `Compilation`, and emits a .NET assembly via the backend compiler.
- `src/bi`: Console REPL. Uses `Balu.Interpretation` to execute incremental script submissions and provides meta commands such as `showSyntax`, `showProgram`, `showVars`, `load`, `emit`, and `graph`.
- `src/Balu.Interpretation`: Runtime execution layer for the REPL and tests. Compiles snippets into in-memory assemblies, executes them, and keeps script globals across submissions.
- `src/Balu.SourceGenerator`: Roslyn source generator used by `src/Balu`. Generates boilerplate for syntax/bound tree children, visitors, and bound tree rewriting.
- `src/Balu.Sdk`: MSBuild SDK package for building Balu projects. It collects `*.b` files and invokes `bc` during `CoreCompile`.
- `src/Balu.VSIX`: Visual Studio extension project with project/item templates.
- `src/Balu.Tests`: xUnit test project for lexer, parser, binder, execution, emitter, source text, and compiler behavior.
- `src/HelloWorld`: Example Balu project using `Balu.Sdk` and sample `.b` files.

## Compiler Pipeline

- Source input starts as `SourceText` and is parsed through `SyntaxTree.Parse` or `SyntaxTree.Load`.
- Lexing and parsing live under `src/Balu/Syntax`.
- Semantic binding lives under `src/Balu/Binding`.
- Symbols live under `src/Balu/Symbols`.
- Lowering lives under `src/Balu/Lowering` and rewrites high-level bound trees into lower-level control-flow forms.
- IL emission lives under `src/Balu/Emit` and uses Mono.Cecil.
- `Compilation` is the central API. Use `Compilation.Create(...)` for normal programs and `Compilation.CreateScript(previous, ...)` for REPL/script-style incremental compilation.

## Syntax And Bound Nodes

Many node classes are `partial`. Boilerplate such as child accessors, visitors, and rewriters is generated by `Balu.SourceGenerator`.

When adding language constructs, usually check or update:

- `SyntaxKind`
- Lexer/parser logic
- Syntax node class
- Binder and bound node classes
- `BoundNodeKind`
- Lowerer if the construct affects control flow
- Emitter if the construct produces IL
- Tests in `src/Balu.Tests`

Do not manually edit generated files under `bin`, `obj`, or generated output unless specifically debugging generated code.

## Useful Commands

From the repository root:

- Build solution: `dotnet build src/Balu.sln`
- Run tests: `dotnet test src/Balu.Tests/Balu.Tests.csproj`
- Run compiler CLI: `dotnet run --project src/bc -- <source-files> [options]`
- Run REPL: `dotnet run --project src/bi`
- Build SDK package: `dotnet build src/Balu.Sdk/Balu.Sdk.csproj`
- Build example project: `dotnet build src/HelloWorld/helloworld.csproj`

The CLI supports options such as `/r`, `/o`, `/s`, `/m`, `/q`, and `/help`.

## Test Conventions

Tests are grouped by compiler area:

- `LexerTests`
- `ParserTests`
- `BinderTests`
- `ExecutionTests`
- `EmitterTests`
- `InterpreterTests`
- `CompilationTests`
- `UnitTests`

Test helpers live in `src/Balu.Tests/TestHelper`.

Common helper patterns:

- `AssertScriptEvaluation` executes code through the interpreter.
- `AssertProgramDiagnostics` checks diagnostics for multi-file compilations.
- `AssertIl`, `AssertSymbols`, and `AssertIlAndSymbols` validate emitted IL and debug symbols.

## Important Notes For Agents

- Prefer small, targeted changes.
- Inspect existing patterns before adding new compiler constructs.
- Keep generated-code responsibilities in `Balu.SourceGenerator`.
- Do not touch `bin` or `obj`.
- Be careful with `src/HelloWorld/hello.b`: it is currently modified in the working tree.
